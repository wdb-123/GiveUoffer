## 项目三：EtherCAT 通信稳定性与多关节压力测试

### 项目背景

客户在一个 EtherCAT 主站下连接多个 eRob 关节时，出现偶发掉 OP、主站掉线错误、多电机 CSP 模式异常、首次启动无法进入 OP 等问题。该问题影响机器人系统稳定性和客户交付体验。

### 个人角色

- 问题定位与复现负责人之一
- SOEM / IGH 主站优化参与者
- 技术支持、研发、客户之间的问题闭环推动者

### 主要工作

- 分析 SOEM 主站和 eRob 从站的状态切换流程
- 排查 EtherCAT AL Status、AL Control、0x130、0x120 等状态寄存器
- 分析 DC 同步、SM 同步、周期时间、主站调度和从站降级条件
- 测试 1ms / 2ms 周期、1kHz 收发、实时内核、CPU 隔离、Intel I350 网卡
- 对比多从站中 eRob 与其他设备表现
- 分析 0xA000 主站掉线错误、掉 OP 后恢复机制
- 协同技术支持和研发确认客户侧解决建议
- 推动“一个主站下统一使用 DC 模式”等方案沟通

### 技术栈

- EtherCAT
- SOEM
- IGH EtherCAT
- DC Sync
- SM Sync
- CiA402
- Linux RT
- C / C++
- 多线程
- 实时通信
- 网卡调优
- 电机状态机
- AL Status / AL Control
- PDO / SDO

### 项目成果

- 形成针对 eRob EtherCAT 掉 OP / 主站掉线的系统性排查方法
- 明确客户使用场景下 DC 同步和主站配置的重要性
- 推动技术支持、研发与客户之间的问题闭环
- 将现场问题沉淀为开源项目 issue、内部技术文档和售后知识库内容

### 简历表达

## 6. 岗位筛选标准

优先考虑：

1. 岗位同时需要机器人系统和 AI 应用能力
2. 公司处于机器人、具身智能、工业 AI、智能制造、AI 硬件方向
3. 岗位能接触客户、需求、产品、交付，而不是只写底层代码
4. 岗位有从 0 到 1 建设空间
5. 岗位需要跨部门推进和复杂项目落地
6. 岗位能补足产品、市场、销售、融资、团队协作能力
7. 初创公司或成长型公司优先，但要求业务方向清晰、真实客户明确

谨慎考虑：

1. 纯维护型岗位
2. 只做内部 IT 运维的岗位
3. 只做简单 RAG 问答，没有业务闭环的岗位
4. 只做传统产品经理、无法体现技术复合优势的岗位
5. 没有客户场景、没有交付闭环、没有成长空间的岗位
