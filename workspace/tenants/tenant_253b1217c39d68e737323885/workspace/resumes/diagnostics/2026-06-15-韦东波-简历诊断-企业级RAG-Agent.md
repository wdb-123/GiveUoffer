# 简历诊断报告（AI 工程师 / Agent 工程师）

**候选人**：韦东波
**输出日期**：2026-06-15
**结论**：整体匹配“AI 应用工程/企业级 RAG / Agent 平台化”岗位，方向清晰。当前内容技术含量高但写作风格偏长文案，缺少标准化可检索结构和对比竞争简历的“先成果后经历”强度。

## 快速评分（定性）
- 职位匹配度：4.4/5
- ATS 友好度：3.2/5（偏叙述、关键词密度可优化）
- 可量化证据：3.8/5（已有部分指标，但散落）
- 业务影响表达：4.0/5（有价值，但缺少可验证边界）
- 可读性与排版：3.1/5（段落较长、信息重复）

## 核心问题
1. 个人信息与职位意向未形成“目标导向区块”，难以让招聘官快速抓取 3 秒卖点。
2. 过多“项目叙述”，缺少统一格式的“动作-结果-价值”表达。
3. 指标虽然有但不完整：如规模、并发、延迟、准确率定义、样本来源等缺口较多。
4. 关键词未分层：LLM/IR/RAG/Agent 关键词存在，但未与技能树绑定，影响匹配检索。
5. 风险项（RAG误召回、数据合规、评测覆盖率）未被单独列为你能处理的工程能力。

## 优化优先级（高->低）
1. 加“职业定位 + 价值主张”前置区：30-40字版本，先告诉招聘官你是什么人。
2. 技能区改为“分层技能图谱”
   - LLM 工具链：RAG、Agent、Text2SQL、检索评测
   - 系统/工程区：Python、FastAPI、文档解析、向量检索、异步任务、日志与追踪
   - 机器人区：ROS2、MoveIt、EtherCAT、CAN/CANopen（按岗位二级加权）
3. 每条经历改为固定模板：
   `职责 + 关键动作 + 量化结果 + 业务影响 + 证据`
4. 所有指标增加“来源/可验证范围”
   - 例如 1000 题评测：是否线上流量、离线回归、与哪套 baseline 对比。
5. 项目顺序按岗位相关度排序，删减低相关细节（如过多机械背景展开）

## 可直接替换的高价值句段
- 把“个人概述”第一段替换为：
  - “具备 2 年 AI 与机器人软件交叉背景，主导企业级 RAG + Agent 系统落地，擅长将技术资料转化为可追溯知识服务，覆盖文档、结构化业务数据与人工审核闭环。”
- 用“成果导向”替换项目描述开头：
  - “主导从 0 到 1 的售前售后 AI 体系建设，使重复咨询分流率约 50%，支持 OpenAI 兼容服务接入并具备评测回归闭环。”
- 把“商业价值”量化表达改为可验证句式：
  - “对比上线前后，基于内部质检样本集，复杂问题首答正确率提升至 >80%（需补充：样本口径、对比周期、CI 周期）。”

## 需补证据（强烈建议补齐）
- 指标来源：1000题评测集是谁定义的、评测脚本版本、抽样周期、误差区间。
- 覆盖与容量：服务并发、平均延迟、可用性/故障率、文档更新频率。
- 技术覆盖：向量库/重排模型版本、Embedding/LLM 使用版本、召回策略参数。
- 产出成果：GitHub 项目下载量是否有时间段口径、Demo 截图/链接可复现性。

## 建议结构（简历骨架）
1. 联系方式（精简）
2. 目标岗位与一句话定位
3. 核心技能（分层）
4. 核心成果（3-4 条，最强指标）
5. 工作经历（2-3 条，动作-结果-影响）
6. 代表项目（按岗位相关度）
7. 教育/论文/专利/荣誉
8. AI 工具与语言
