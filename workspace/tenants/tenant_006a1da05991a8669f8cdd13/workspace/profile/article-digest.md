# 韦东波 - 项目证据库

用于岗位匹配、简历定制、面试故事和 Boss 沟通话术。优先把这些证据映射到机器人系统、机器人软件、具身智能应用、AI + 机器人复合岗位。

## 一句话定位

机器人系统工程背景出身，能把底层通信、客户问题、知识治理和大模型 Agent 串成可交付业务系统的 AI + 机器人复合型工程负责人。

更市场化表达：擅长把机器人行业里的复杂技术问题，沉淀成可复用的软件工具、知识系统和 AI Agent 产品。

## 核心方向

- 机器人底层系统与软件生态：eRob 机器人关节、EtherCAT、CANopen、CAN、ROS2、MoveIt、URDF、SOEM、IGH EtherCAT、CiA402、PDO/SDO、CSP/CST/PP/PT、实时 Linux、通信稳定性、运动控制调试。
- 企业级 AI 系统落地：RAG、Agent、企业知识库、售后问答系统、文档解析、知识治理、检索评测、OpenAI-compatible API、CLI、FastAPI、私有化模型部署、业务闭环、评测闭环、失败样本回流。
- AI + 机器人复合方向：具身智能应用、机器人解决方案、机器人开发者生态、技术支持产品化、售后智能化、工业 AI 应用。
- 具身智能数据基建方向：机器人训练数据、多模态数据、机器人状态、轨迹、动作序列、控制指令、仿真数据、数据 Pipeline、数据质量评估、数据资产管理、数据闭环、DataOps / MLOps。

## 项目一：ZeroErr GPT / TechChat 企业级售后知识问答系统

**角色：** AI 系统负责人、RAG / Agent 架构设计与落地负责人、知识治理和评测闭环负责人。

**背景：** 公司产品为 eRob 机器人关节模组，售后问题涉及产品手册、通信协议、驱动使用、FAQ、调试经验、错误码、对象字典、表格、图片等复杂资料。传统售后依赖人工经验，问题分散在文档、群聊、技术支持和研发人员中。

**关键工作：**

- 从 0 到 1 搭建企业级售后问答系统。
- 整理产品手册、通信协议、FAQ、售后经验、表格和图片资料。
- 设计文档解析、知识切分、章节结构、标题增强、关联问题增强。
- 构建语义检索、关键词检索、混合检索和重排流程。
- 建立问题集、标准测试集和自动化评测体系。
- 设计失败样本回流机制。
- 设计 Evidence API，返回来源、章节、页码、原文片段、表格、图片摘要。
- 封装 OpenAI-compatible API 和 CLI，支持聊天、证据检索、健康检查、技能安装。
- 支持 OpenAI SDK、OpenWebUI、Dify、LangChain、Codex、OpenClaw 等生态接入。

**技术栈：** RAG、Agent、Python、FastAPI、OpenAI-compatible API、CLI、vLLM、Qwen、DeepSeek、m3e-large、bge-reranker-v2-m3、LangChain、Dify、OpenWebUI、文档解析、混合检索、重排、评测系统。

**结果：**

- 将产品手册、通信协议、FAQ、售后经验沉淀为可检索、可引用、可评测的知识服务。
- 标准测试集约 1000 条。
- 基础 RAG Top10 命中约 96.8% 以上，内部测试集 Top-10 召回率达到约 98.0%。
- 通过 Agent 补救机制覆盖基础 RAG miss 样本。
- 形成“知识治理 + RAG + Evidence Tool + 评测闭环 + 售后业务闭环”的完整方法论。

**适合讲给：** AI 应用工程师、RAG 工程师、Agent 工程师、AI 解决方案工程师、售后智能化、企业知识库负责人、机器人 AI 系统工程师。

## 项目三：EtherCAT 通信稳定性与多关节压力测试

**角色：** 问题定位与复现负责人之一、SOEM/IGH 主站优化参与者、技术支持/研发/客户之间的问题闭环推动者。

**关键工作：**

- 分析 SOEM 主站和 eRob 从站状态切换流程。
- 排查 EtherCAT AL Status、AL Control、0x130、0x120 等状态寄存器。
- 分析 DC 同步、SM 同步、周期时间、主站调度和从站降级条件。
- 测试 1ms/2ms 周期、1kHz 收发、实时内核、CPU 隔离、Intel I350 网卡。
- 分析 0xA000 主站掉线错误、掉 OP 后恢复机制。
- 推动“一个主站下统一使用 DC 模式”等方案沟通。

**结果：**

- 形成针对 eRob EtherCAT 掉 OP / 主站掉线的系统性排查方法。
- 明确客户使用场景下 DC 同步和主站配置的重要性。
- 将现场问题沉淀为开源项目 issue、内部技术文档和售后知识库内容。

**适合讲给：** 控制系统工程师、机器人通信工程师、机器人系统工程师、工业通信岗位、现场问题闭环型岗位。

## 筛选标准

**优先考虑：**

- 岗位同时需要机器人系统和 AI 应用能力。
- 公司处于机器人、具身智能、工业 AI、智能制造、AI 硬件方向。
- 岗位能接触客户、需求、产品、交付，而不是只写底层代码。
- 岗位有从 0 到 1 建设空间。
- 岗位需要跨部门推进和复杂项目落地。
- 初创公司或成长型公司优先，但要求业务方向清晰、真实客户明确。

**谨慎考虑：**

- 纯维护型岗位。
- 只做内部 IT 运维的岗位。
- 只做简单 RAG 问答，没有业务闭环的岗位。
- 只做传统产品经理，无法体现技术复合优势的岗位。
- 没有客户场景、没有交付闭环、没有成长空间的岗位。

## 面试故事

### 故事一：从机器人软件工程师转向企业 AI 系统负责人

先在机器人关节通信、EtherCAT、CANopen、ROS2、客户调试中积累真实业务问题，再把这些问题沉淀进企业知识库，建设成 RAG / Agent 系统，让售后、研发、客户都可以复用这些经验。

### 故事二：从客户现场问题到产品化知识系统

客户的问题不是一次性解决就结束，而是要变成公司可以复用的能力。把客户问题、技术支持经验、研发定位过程沉淀成文档、FAQ、知识库、评测集和 Agent 工具，让组织不再依赖单个人的记忆。

### 故事三：复杂系统问题的单点突破

EtherCAT 掉 OP、多电机 CSP、实时 Linux、DC 同步这类问题涉及主站、从站、实时调度、网络、状态机和客户环境。候选人能拆解问题、复现问题、协同研发和技术支持，最后形成工程化方案。
