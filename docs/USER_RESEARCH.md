# Career-Ops 用户调研与用户画像

日期：2026-06-02

## 当前产品阶段判断

Career-Ops 目前处在产品时间表的 **Week 1：产品发现 / 产品数据调研阶段**。

现在还不应该直接进入大规模开发或公开发布。当前最重要的是验证三个问题：

1. 谁是真正高价值用户？
2. 他们现在的求职流程哪里最痛？
3. Career-Ops 的核心能力，是不是比现有工具更适合解决这些痛点？

结论：**需要去社交渠道寻找真实用户，但方式应该是小样本深访 + 社区观察 + 轻量问卷，而不是一开始大规模推广。**

## 为什么现在要找真实用户

Career-Ops 不是一个纯工具脚本，它要解决的是复杂求职流程：

- 职位筛选
- 简历定制
- 申请追踪
- 面试故事准备
- 反馈学习
- 长周期求职决策

这些痛点不能只靠开发者自己想象。尤其是当前 AI 求职工具很多，用户对“AI 改简历”“自动投递”“ATS 打分”“求职 tracker”的真实感受很分裂。产品必须先确认用户到底信任什么、不信任什么。

## 初步外部信号

近期公开讨论和资料显示：

- 很多求职者已经使用 AI 做简历、求职和面试准备，但担心 AI 改写让简历变得泛化、像关键词堆砌。
- 用户抱怨求职工具太碎片化：简历工具、ATS 扫描、投递 tracker、面试准备、公司研究分散在多个产品里。
- 用户不喜欢低质量自动海投，也担心自动化让所有申请看起来更相似。
- 很多用户真正缺的不是“再生成一份简历”，而是一个能帮他们判断岗位值不值得投、为什么投、怎么跟踪结果的完整系统。
- 有用户明确提到，好机会常来自难监控的渠道，比如小众社区、公司官网、Telegram / RSS / niche job board，而不是大平台聚合器。

## 用户招募策略

### 第一阶段：5 个深访用户

目标：验证痛点，不验证规模。

建议找：

- 2 个技术岗位求职者
- 1 个转行 / 职业方向重构用户
- 1 个中高级候选人
- 1 个 AI 工具重度用户

筛选条件：

- 最近 3 个月正在求职或刚结束求职
- 投递过至少 20 个岗位
- 用过 ChatGPT / Claude / 简历工具 / ATS 工具之一
- 愿意展示自己的真实求职流程或匿名截图

### 第二阶段：10-20 个轻量问卷用户

目标：验证痛点排序。

问卷不要太长，控制在 8-10 个问题。

### 第三阶段：3-5 个灰度测试用户

目标：验证产品是否可用。

这些用户应该真实跑一遍：

1. 配置 CV 和 profile
2. 粘贴一个岗位 URL
3. 生成评估报告
4. 生成简历
5. 写入 tracker
6. 给系统反馈

## 深访问题

### 求职流程

1. 你现在完整的求职流程是什么？
2. 你每周大概看多少岗位，投多少岗位？
3. 你怎么判断一个岗位值不值得投？
4. 你现在用什么工具管理投递进度？
5. 哪一步最耗时间？

### AI 工具使用

1. 你是否用 AI 改简历、写 cover letter 或准备面试？
2. AI 哪些地方真的帮到了你？
3. AI 哪些地方让你不信任？
4. 你是否担心 AI 改出来的简历太泛化？
5. 你是否愿意让工具自动投递？为什么？

### 简历和岗位匹配

1. 你会不会针对每个岗位定制简历？
2. 你怎么判断简历是否匹配 JD？
3. 你是否遇到过“明明匹配但没回复”的情况？
4. 你最需要工具帮你解释什么？

### 产品验证

1. 如果一个工具能帮你评分岗位、生成报告、定制简历、记录 tracker，你会用吗？
2. 你最想先用哪一个功能？
3. 你最担心这个工具哪里不靠谱？
4. 你愿意为本地开源工具付出什么成本：配置时间、学习成本、订阅、贡献反馈？

## 用户画像

应届毕业生是一个单独细分人群，详细痛点、画像和功能决策见 `docs/GRADUATE_USER_RESEARCH.md`。当前建议是：先作为独立 Graduate Mode 验证，不直接替代 v1 主 ICP。

### Persona 1：高级技术求职者

| 项目 | 内容 |
|------|------|
| 名称 | 高级技术求职者 |
| 典型背景 | 3-10 年经验的软件、AI、数据、机器人、平台工程师 |
| 当前状态 | 想换到更高质量、更匹配长期方向的岗位 |
| 核心目标 | 少投但投准，找到真正匹配自己能力和薪酬目标的岗位 |
| 痛点 | 岗位太多、JD 信息噪音高、简历定制耗时、申请进度分散 |
| 现有替代方案 | Excel / Notion tracker、ChatGPT 改简历、LinkedIn、招聘网站 |
| 对 Career-Ops 的价值感 | 能把 JD 评估、简历定制、tracker 和面试故事串起来 |
| 风险 | 不愿花太多时间配置；如果报告不准，会很快失去信任 |
| 关键功能 | 高质量岗位评分、证据化匹配、定制简历、申请状态跟踪 |

### Persona 2：职业转型 / 方向重构用户

| 项目 | 内容 |
|------|------|
| 名称 | 职业转型用户 |
| 典型背景 | 从传统软件、硬件、科研、咨询、运营转向 AI / 数据 / 产品 / 机器人等方向 |
| 当前状态 | 有经历和项目，但不知道如何讲成目标岗位需要的故事 |
| 核心目标 | 找到可迁移能力，并形成可信的求职叙事 |
| 痛点 | 不知道自己适合哪些岗位；简历容易写散；面试故事不成体系 |
| 现有替代方案 | 职业咨询、简历服务、AI 聊天工具、课程社群 |
| 对 Career-Ops 的价值感 | 能通过 archetype、proof points、story bank 帮他建立职业叙事 |
| 风险 | 可能期待工具替他决定职业方向，需要明确工具只是辅助判断 |
| 关键功能 | 职业原型匹配、简历重构、故事库、岗位推荐逻辑 |

### Persona 3：AI 工具重度用户 / 开源工具用户

| 项目 | 内容 |
|------|------|
| 名称 | AI 工具重度用户 |
| 典型背景 | 熟悉 Claude Code、Codex、Cursor、Gemini、OpenCode、GitHub |
| 当前状态 | 已经用 AI 辅助求职，但流程分散在多个 prompt 和文件中 |
| 核心目标 | 把求职流程变成可复用、可自动化、可审计的本地系统 |
| 痛点 | Prompt 不稳定；工具之间数据不能流转；结果不可追踪 |
| 现有替代方案 | 自己写脚本、Notion、ChatGPT 项目、各种 resume SaaS |
| 对 Career-Ops 的价值感 | 本地文件、开源、可扩展、可让 agent 直接修改 |
| 风险 | 会要求更强扩展性和更清晰架构；容易发现系统缺陷 |
| 关键功能 | 模式文件、扫描器扩展、dashboard、测试、数据契约 |

### Persona 4：求职教练 / 职业顾问

| 项目 | 内容 |
|------|------|
| 名称 | 求职教练 |
| 典型背景 | 帮多个候选人做简历、定位、面试、投递策略 |
| 当前状态 | 服务交付高度依赖人工整理和经验判断 |
| 核心目标 | 提高服务效率，同时保持个性化质量 |
| 痛点 | 客户资料分散；每次评估岗位和改简历都重复劳动；难以追踪长期结果 |
| 现有替代方案 | Notion、飞书表格、Google Docs、ChatGPT、简历模板 |
| 对 Career-Ops 的价值感 | 可以变成结构化客户求职操作系统 |
| 风险 | 多用户数据隔离、隐私、模板化输出质量是主要顾虑 |
| 关键功能 | 多 profile、报告模板、tracker、故事库、导出能力 |

## 优先用户选择

v1 不建议同时服务所有人。

优先级：

1. **高级技术求职者**
2. **AI 工具重度用户**
3. **职业转型用户**
4. 应届毕业生（通过独立 Graduate Mode 验证）
5. 求职教练

原因：

- Career-Ops 当前是本地、文件驱动、AI coding CLI 友好的产品。
- 高级技术求职者和 AI 工具用户最能接受配置成本。
- 他们也最容易理解“质量优先，不自动海投”的产品原则。
- 应届毕业生痛点很强，但需要更强引导、更低配置门槛和校招专用流程，不应直接混入主线体验。

## 需要验证的关键假设

| 假设 | 验证方式 | 通过标准 |
|------|----------|----------|
| 用户愿意花 30-60 分钟配置本地求职系统 | 深访 + 灰度测试 | 3/5 用户愿意完成配置 |
| 用户更需要岗位决策系统，而不只是简历生成器 | 深访问题排序 | 岗位判断 / tracker / 简历定制进入 Top 3 痛点 |
| 用户不信任黑箱 AI 简历改写 | 社区观察 + 深访 | 多数用户要求看到改动依据 |
| 用户愿意给系统反馈，让它学习偏好 | 灰度测试 | 3/5 用户愿意在评估后反馈一次 |
| 本地开源是差异化优势 | 技术用户访谈 | 技术用户明确偏好本地可控 |

### 不应该现在做

- 不要马上公开大规模发布。
- 不要先做复杂 dashboard。
- 不要把产品定位成自动海投工具。
- 不要只靠问卷替代真实访谈。
- 不要在没有真实用户反馈前扩展太多功能。
