# 应届毕业生求职痛点与产品功能决策

日期：2026-06-03

## 结论

应届毕业生可以成为 Career-Ops 的重要用户群，但不应该直接套用当前面向中高级技术求职者的产品形态。

当前 Career-Ops 的核心能力是“岗位评估 + 简历定制 + tracker + 反馈学习”。这对有明确目标和较多经历的用户很有效，但应届生的问题更靠前：

1. 不知道自己该投什么岗位。
2. 不知道自己的课程、项目、实习能证明什么。
3. 不会判断岗位是否适合应届生。
4. 校招节奏、批次、网申、笔试、群面、实习转正信息分散。
5. AI 已经高频使用，但容易生成同质化简历和空泛面试回答。

所以，如果要服务应届生，v1 功能重点应该从“高阶岗位决策系统”扩展为：

> 应届生求职路径规划 + 经历资产化 + 岗位适配判断 + 校招进度管理。

## 应届生核心痛点

### 1. 职业方向不清

表现：

- 不知道专业能投哪些岗位。
- 看到 AI、新能源、具身智能、大模型等热门方向，但不知道自己是否够资格。
- 同时准备校招、考研、考公、实习、春招补录，路径混乱。

产品机会：

- 做“职业路径探索”和“岗位族谱”。
- 把专业、课程、项目、实习映射到可投岗位。
- 给出主攻、备选、保底三类方向。

### 2. 证明材料不足

表现：

- 简历里只有课程作业、竞赛、实验室项目、社团经历。
- 不知道如何把课程项目写成岗位需要的能力证据。
- 缺少量化结果，不会讲项目价值。

产品机会：

- 建立“经历资产库”。
- 把课程、项目、论文、竞赛、实习、社团经历拆成技能、成果、证据和面试故事。
- 提供项目补强建议，而不是只改简历措辞。

### 3. 岗位适配判断弱

表现：

- 不会判断 JD 中哪些是硬要求、哪些是加分项。
- 分不清“应届可投”“实习转正”“社招伪装校招”“需要真实生产经验”的岗位。
- 容易被 title 吸引，忽略地点、批次、笔试、转正率和培养机制。

产品机会：

- 为应届生建立专门评分维度：
  - 应届友好度
  - 培养机制
  - 实习/项目可迁移度
  - 笔试/面试准备成本
  - 城市与生活成本
  - 转正或成长空间

### 4. 校招流程复杂

表现：

- 秋招、春招、补录、提前批、实习、转正、宣讲会、笔试、群面流程交错。
- 投递入口分散在官网、牛客、学校就业网、Boss、脉脉、公众号、内推群。
- 很难追踪每家公司当前阶段。

产品机会：

- 做校招 tracker。
- 支持批次、岗位状态、笔试时间、面试轮次、内推人、截止日期。
- 增加提醒和下一步建议。

### 5. AI 使用高频但低信任

表现：

- 用 AI 改简历、写自我介绍、准备面试，但产出容易同质化。
- AI 会夸大经历，或者把学生项目写得像生产项目。
- 面试时容易被追问穿帮。

产品机会：

- 输出“证据链式简历”：每个简历 bullet 对应真实经历来源。
- 标记“可讲”和“不可讲”的内容。
- 生成面试追问和回答边界。

### 6. 心理压力和信息不对称

表现：

- 投递很多没有反馈，不知道是简历问题、岗位不匹配还是流程没开始。
- 周围同学 offer 信息带来焦虑。
- 对薪资、城市、行业长期发展缺乏判断。

产品机会：

- 给出“申请质量”而不是只统计投递数量。
- 做周报：本周看了多少岗位、投了哪些、哪些应该放弃、下周重点是什么。
- 引导用户减少无效投递。

## 应届生用户画像

### Persona A：普通本科技术应届生

| 项目 | 内容 |
|------|------|
| 背景 | 普通本科，计算机/电子/自动化/机械/数据相关专业 |
| 状态 | 有课程项目和少量实习，正在秋招或春招 |
| 目标 | 找到第一份技术岗，避免盲投 |
| 最大痛点 | 不知道自己能投什么；项目太普通；简历没有亮点 |
| 关键功能 | 岗位方向推荐、项目经历资产化、应届友好度评分、校招 tracker |
| 风险 | 不愿配置复杂本地项目，更需要简单引导和模板 |

### Persona B：硕士应届生 / 科研项目型候选人

| 项目 | 内容 |
|------|------|
| 背景 | 硕士研究生，有论文、实验室项目、工程 demo 或产业合作 |
| 状态 | 想从科研/实验室经历转向产业岗位 |
| 目标 | 把研究经历讲成公司岗位需要的工程价值 |
| 最大痛点 | 论文、项目和岗位 JD 之间的映射不清；不知道怎么降维表达 |
| 关键功能 | 研究经历产品化、JD 匹配评分、技术面故事库、简历定制 |
| 风险 | 如果工具只做通用简历优化，价值不够 |

### Persona C：非技术专业转 AI / 运营 / 产品方向应届生

| 项目 | 内容 |
|------|------|
| 背景 | 经管、人文社科、设计、语言、传媒等专业 |
| 状态 | 想转到 AI 相关运营、产品、数据分析、新媒体、电商等岗位 |
| 目标 | 找到可迁移能力和低门槛切入点 |
| 最大痛点 | 不知道哪些 AI 技能需要补；担心专业不对口 |
| 关键功能 | 转型路径建议、技能 gap 分析、作品集建议、岗位分层 |
| 风险 | 容易期待工具替自己做职业决定，需要明确边界 |

### Persona D：校招高压海投型用户

| 项目 | 内容 |
|------|------|
| 背景 | 已投递大量岗位但反馈少 |
| 状态 | 焦虑、追求效率，容易被“一键投递”吸引 |
| 目标 | 提高回复率，减少无效投递 |
| 最大痛点 | 不知道为什么没回复；投递记录混乱；无法复盘 |
| 关键功能 | 投递质量分析、tracker、简历/JD 匹配解释、复盘周报 |
| 风险 | 如果产品迎合海投，会违背 Career-Ops 质量原则 |

## 功能决策

### 应该做

| 功能 | 优先级 | 原因 |
|------|--------|------|
| 应届生岗位适配评分 | P0 | 应届生最缺的是判断岗位是否值得投 |
| 经历资产库 | P0 | 解决“没有亮点”和“不会表达” |
| 校招 tracker | P0 | 校招流程比社招更复杂，强需求 |
| JD 硬要求 / 加分项拆解 | P0 | 帮用户判断能不能投 |
| 简历 bullet 证据链 | P1 | 防止 AI 夸大，提升可信度 |
| 面试追问模拟 | P1 | 应届生容易被项目追问击穿 |
| 周计划 / 求职复盘 | P1 | 帮用户从焦虑海投转向质量管理 |
| 技能 gap 和补强项目建议 | P1 | 适合转型和普通项目背景用户 |

### 暂时不该做

| 功能 | 原因 |
|------|------|
| 一键海投 | 违背产品伦理和质量定位 |
| 大而全职业测评 | 容易泛化，短期难验证 |
| 复杂 dashboard 优先 | 应届生更需要引导流程，不是数据看板 |
| 自动编造项目经历 | 高风险，会伤害用户面试可信度 |
| 大规模校招岗位爬虫 | 先验证 tracker 和适配评分，再扩展数据源 |

### 可以后做

| 功能 | 条件 |
|------|------|
| 校招信息源聚合 | 当 tracker 和岗位评分验证有效后 |
| 社群内推线索管理 | 当真实用户开始提供内推和群信息后 |
| 学校就业网适配 | 当目标学校或用户群明确后 |
| 多用户教练版 | 当求职教练 persona 被验证后 |

## 对 Career-Ops v1 的影响

如果把应届生纳入 v1，产品范围会变大。建议不要把“应届生全流程版本”作为当前 v1 主线，而是做一个受控的子模式：

> `graduate mode`：面向应届生的岗位适配、经历资产化和校招 tracker。

### Graduate Mode MVP

最小版本只做 5 件事：

1. 输入用户背景：专业、学历、目标城市、项目/实习/课程、求职方向。
2. 输入岗位 JD 或校招链接。
3. 输出应届生适配评分。
4. 输出经历改写建议和证据链。
5. 写入校招 tracker，记录批次、状态、截止日期和下一步。

### Graduate Mode 评分维度

| 维度 | 权重 | 说明 |
|------|------|------|
| 应届友好度 | 20% | 是否明确接受应届/校招/实习转正 |
| 经历匹配度 | 20% | 项目、课程、实习是否能支撑岗位要求 |
| 技能 gap | 15% | 缺口是否可在短期补齐 |
| 成长和培养机制 | 15% | 是否有导师、轮岗、培养、明确晋升 |
| 求职成本 | 10% | 笔试、面试、地点、准备成本 |
| 薪资和城市适配 | 10% | 是否符合生活成本和预期 |
| 风险信号 | 10% | 是否伪校招、培训贷、低质量外包、信息不透明 |

## 推荐功能路线

### Phase G1：调研验证

- 找 5 个应届生访谈。
- 收集 20 个真实校招 JD。
- 收集 5 份匿名简历或项目经历。
- 验证他们是否愿意使用“岗位评分 + 经历资产化 + tracker”。

### Phase G2：文档型原型

- 新增 `modes/graduate.md`。
- 新增 `templates/graduate-tracker.md`。
- 新增 `data/graduate-applications.md`。
- 先不做 UI。

### Phase G3：灰度测试

- 让 3 个应届生各跑 3 个岗位。
- 看他们是否能根据评分减少无效投递。
- 看经历改写是否能在面试中讲得住。

### Phase G4：产品化

- 如果 G3 有效，再考虑 dashboard、校招信息源聚合、提醒和批量处理。

## 需要继续验证的问题

1. 应届生愿不愿意花时间录入项目经历？
2. 他们更想要“岗位推荐”还是“简历改写”？
3. 校招 tracker 是否比现有 Excel / Notion 更有价值？
4. 应届生是否能接受“少投高质量”的理念，还是更偏好海投？
5. Graduate Mode 是否会稀释 Career-Ops 当前面向高级技术用户的定位？

## 产品判断

应届生市场大、痛点强，但配置耐心低、付费能力和信任门槛都不同。

因此建议：

- **不要把应届生作为当前主线 v1 ICP。**
- **可以把应届生作为一个独立子模式验证。**
- **先做 Graduate Mode 的文档型 MVP，不做复杂前端。**
- **功能优先级聚焦：岗位适配评分、经历资产库、校招 tracker。**
